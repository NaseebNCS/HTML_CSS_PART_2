Welcome to another section of the HTML and CSS Part 2 series! In this section, we will learn how to write maintainable CSS code. First, we’ll cover CSS best practices to make your code cleaner and easier to manage. Then, we’ll explore CSS variables and techniques for removing duplicate code. After that, we’ll dive into Object-Oriented CSS (OOCSS), which helps create reusable and modular styles. Finally, we’ll discuss BEM (Block Element Modifier), a popular naming convention for CSS classes. This section is very important because writing well-structured and maintainable CSS ensures that you can modify your code anywhere without breaking it.

CSS Best Practices

One of the key practices in CSS is writing clean and maintainable code. A major factor in achieving this is consistent naming conventions.

In real-world web development projects, you often work in teams. When different developers join a project and use their own naming styles, the code can become confusing and messy. Without a standard, it’s hard to maintain or scale the project.

To avoid this, pick a naming convention for your CSS classes and IDs and stick to it throughout the entire project. This guideline ensures that everyone on the team writes code in a consistent and understandable way.

Example: Consistent Naming
Instead of mixing styles like this: 

<div class="headerTop">Header</div>
<div id="main_body">Main Content</div>
<div class="footerSection">Footer</div>

Use a consistent convention, for example kebab-case (all lowercase, words separated by hyphens):

<div class="header-top">Header</div>
<div class="main-body">Main Content</div>
<div class="footer-section">Footer</div>

And the corresponding CSS:
.header-top {
    background-color: #f8f9fa;
    padding: 20px;
}

.main-body {
    font-size: 16px;
    line-height: 1.5;
}

.footer-section {
    background-color: #333;
    color: #fff;
    padding: 10px;
    text-align: center;
}

Create Logical Sections in your stylesheet

For a small project, you might use a single CSS stylesheet. However, for larger projects, it’s better to split your styles into multiple stylesheets to keep things organized. This is where CSS preprocessor tools like Sass or LESS become useful.

In a small project, you can still have one stylesheet but organize it using different containers or sections within the file. For larger projects, you divide your CSS into separate files like one for layout, one for typography, one for colors, etc. and then combine them using a preprocessor. This approach keeps your code manageable, easier to maintain, and more scalable. 

Break your code in different sections using comments.

Avoid Overly Specific Selectors

This is a common issue among many developers. Using overly specific or deeply relational selectors can make your CSS messy and hard to maintain. If your HTML structure changes, these selectors may stop working, causing your styles to break. 

<div class="nav">
  <ul class="items">
    <li class="item">Link 1</li>
    <li class="item">Link 2</li>
    <li class="item">Link 3</li>
  </ul>
</div>

Avoid these selectors
div.nav > ul.items > li{}

Instead of that
<div class="nav">
  <ul class="nav-items">
    <li class="nav-item">Link 1</li>
    <li class="nav-item">Link 2</li>
    <li class="nav-item">Link 3</li>
  </ul>
</div>

.nav-item{}

Avoid Using !important

Try to avoid using the !important keyword as much as possible. If you feel the need to use it, it usually means something is wrong in your CSS, like the selectors are not structured properly. Instead of relying on !important, try to write more specific and well-organized selectors.

Sort CSS Properties

Sorting CSS properties is not mandatory, but it makes your code look more organized and professional. To sort your properties, select all the CSS code you want to arrange, press Ctrl + Shift + P, search for "Sort," and choose the option to sort your properties. This will arrange them alphabetically (from A to Z) or in ascending order.

Take Advantage of Style Inheritance

When you have a container with multiple child elements, you might want all of them to share the same style, like a font family or text color. Instead of applying the same style to each element individually, you can take advantage of CSS inheritance or reusable classes.

By default, some CSS properties (like color, font-family) are inherited by child elements. But certain elements, like <a> (links), do not automatically inherit some styles. In that case, you would need to explicitly apply the same style.

To avoid repeating yourself (a principle called DRY Don’t Repeat Yourself), you can create a CSS class with the desired style and assign it to all elements that should share that style. This way, your code stays clean, maintainable, and consistent. 

<div class="container">
    <p>This paragraph inherits the container's font and color.</p>
    <p>Another paragraph also inherits the same style.</p>
    <a href="#">This link may not inherit color by default</a>  
</div>

.container {
        font-family: Arial, sans-serif;
        color: darkblue;
    }

Notice: In some browsers, <a> elements do not automatically inherit the color. You may need to explicitly style them. 

<div>
  <p class="text-style">This paragraph uses the reusable class.</p>
  <p class="text-style">Another paragraph with the same class.</p>
  <a href="#" class="text-style">This link now shares the same style</a>
</div>

.text-style {
        font-family: Arial, sans-serif;
        color: darkblue;
    }

Benefits:

  • Avoid repeating the same CSS for multiple elements.
  • Make your code cleaner and easier to maintain.
  • Keep styles consistent across your webpage.

CSS Variables (Custom Properties)

What are CSS Variables?
CSS variables, also called CSS custom properties, allow you to store values in one place and reuse them throughout your stylesheet. This helps keep your code DRY (Don't Repeat Yourself), meaning you don’t have to rewrite the same values multiple times.

How to Create CSS Variables:
You can define CSS variables inside the :root selector. The :root selector represents the highest-level element in the HTML document (essentially the <html> element).

Rules for CSS Variables:

  • Variable names must start with double hyphens (--).
  • You can use these variables anywhere in your CSS using the var() function.
<div class="one"></div>
<div class="two"></div>

Define variables in :root
:root{
      --primary-color: #f00;
      --border-size: 2px;
      --border-radius: 10px;
      --margin: 1rem;
      --secondary-color: #2ecc71;
      --font-size: 16px;
}

Use variables in your CSS 
body {
      font-size: var(--font-size);
      color: var(--primary-color);
      background-color: var(--secondary-color);
}

div{
      width: 200px;
      height: 200px;
}

.one{
      background: var(--border-radius);
      margin-left: var(--margin);
}

.two{
      border: var(--border-size) solid var(--primary-color);
}

h1 {
    color: var(--primary-color);
}

p {
    color: var(--secondary-color);
}

Description of Above Code:

  • --primary-color, --secondary-color, and --font-size are CSS variables.
  • var(--primary-color) is used to apply the variable wherever needed.
  • If you ever want to change the main color of your website, you only need to change it in :root, and it will automatically update everywhere.

Bonus Tip: You can even override CSS variables inside specific elements:

section {
        --primary-color: #e74c3c; Override primary color only in this section
        color: var(--primary-color);
}

This makes your styling flexible and easy to maintain.

Object-Oriented

If you have experience in programming, you have probably heard the term OOP (Object-Oriented Programming). OOP is a way of creating reusable components in code. The same concept can be applied in CSS to make reusable and maintainable styles.

When we reuse styles, we don’t have to repeat code, which results in a smaller, cleaner, and easier-to-maintain stylesheet.

OOP CSS is based on two main principles, which we’ll cover here:

Principle 1: Separate Containers from Content

The first principle says we should separate the container from the content inside it.

For example, let's create a header with a class .hero and a button inside it with a class .btn: 

<header class="hero">
  <button class="btn">Click Me</button>
</header>

<aside class="sidebar">
  <button class="btn">Subscribe</button>
</aside>

Before OOP CSS, you might style buttons like this:

.hero .btn {
      padding: 10px 20px;
      background-color: blue;
      color: white;
      border: none;
      border-radius: 5px;
}

If you have another button in the sidebar, you would need to repeat the styles, which is not efficient.

With OOP CSS, we separate the container (.hero) from the content (.btn): 

.btn {
      padding: 10px 20px;
      color: white;
      border: none;
      border-radius: 5px;
}

Now, the .btn class can be used anywhere in the website, without tying it to a specific container.

Principle 2: Separate Structure from Skin

The second principle says we should separate the structure of a component from its visual appearance (skin).

For example, you might want one button to have a red background and another to have a gold background:

⩽button class="btn btn-red">Click Me⩽/button>
⩽button class="btn btn-gold">Subscribe⩽/button>

Without OOP CSS, you might duplicate the button structure for each color:

.btn-red {
        padding: 10px 20px;
        background-color: red;
        color: white;
        border: none;
        border-radius: 5px;
}

.btn-gold {
        padding: 10px 20px;
        background-color: gold;
        color: white;
        border: none;
        border-radius: 5px;
}

Notice the repeated code? That’s not maintainable.

With OOP CSS, we separate the structure from the skin:

<button class="btn btn-primary">Click Me</button>
<button class="btn btn-secondary">Subscribe</button>

Structure 
.btn {
        padding: 10px 20px;
        color: white;
        border: none;
        border-radius: 5px;
}

Skin 
.btn-primary {
        background-color: red;
}

.btn-secondary {
        background-color: gold;
}

Now, the structure (padding, border, radius) is defined once in .btn, and the skin (color) is defined separately.

This approach allows you to reuse components easily and change their appearance without rewriting structure.

BEM

What is BEM?
BEM stands for Block, Element, Modifier. It is a methodology for writing CSS that makes your code more modular, reusable, and maintainable. Think of a web page as a collection of blocks (components or modules), each containing elements. You can style these blocks and elements, and sometimes modify them to create variations.

Key points about BEM:

  • Block: A standalone component like a card, header, or form.
  • Element: A part of a block that has no standalone meaning, such as a card’s header, body, or price.
  • Modifier: A flag that changes the appearance or behavior of a block or element, such as highlighting a card or marking a button as active.

Example of BEM naming: 

Block: card
<div class="card card--popular">
    <span class="t-r">Element: card header</span>
    <div class="card__header">Product Name</div>

    <span class="t-r">Element: card body</span>
    <div class="card__body">Product Description</div>
    
    <span class="t-r">Element: card price</span>
    <div class="card__price">$99</div>
    <button class="btn btn--primary">Buy Now</button>
</div>

Explanation of Above Code:

  • card👉 Block
  • card__header👉 Element of the card block
  • card--popular👉 Modifier of the card block
  • btn👉 Another block (button)
  • btn--primary👉 Modifier of the button

BEM helps you avoid complex selectors, makes styles predictable, and improves collaboration in larger projects.

General CSS Best Practices

1. Naming Conventions

Use consistent naming for classes and IDs. Common conventions:

  • PascalCase👉 CardHeader
  • camelCase👉 cardHeader
  • kebab-case👉 card-header

2. Organizing CSS

  • Small projects: One stylesheet is enough; use comments for sections.
  • Large projects: Split CSS into multiple files and combine them using Webpack, Rollup, or Parcel.

3. Avoid Over-Specific Selectors

  • Limit nesting to 2–3 levels.
Too specific
.card .card__body p span {
         color: red; 
}

Better
.card__body span { 
         color: red;
}

4. Avoid !important Use it only if absolutely necessary. Overuse makes debugging difficult.

5. Sort CSS Properties Sorting properties makes your code easier to read and maintain.

.card__body {
          display: flex;
          flex-direction: column;
          padding: 1rem;
          margin: 0.5rem;
          color: #333;
}

6. Use Inheritance to Reduce Duplication

body {
    font-family: Arial, sans-serif;
    color: #333;
}
p {
    font-size: 16px; inherits color from body 
}

7. Use CSS Variables (Custom Properties)

:root {
  --primary-color: #007bff;
  --secondary-color: #6c757d;
  --font-size: 16px;
}

.btn {
  background-color: var(--primary-color);
  font-size: var(--font-size);
}

.btn--secondary {
  background-color: var(--secondary-color);
}

8. Object-Oriented CSS (OOCSS) Principles

OOCSS is about creating reusable components by separating:

  1. Container and content
  2. Structure and skin (style/appearance)

Using BEM, OOCSS, and CSS variables together makes your code clean, scalable, and easy to maintain.
