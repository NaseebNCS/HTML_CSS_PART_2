What is ANIMATION

Animation is the art of creating the illusion of movement. It works by showing a fast sequence of static images, drawings, or objects. Because these images change very quickly, our brain thinks that the objects are moving. In simple words, when something moves from an initial position to a final position or from final to initial this movement is called animation.

What is GSAP

GSAP stands for GreenSock Animation Platform. It is a powerful JavaScript animation library used to create smooth and complex animations on websites. With GSAP, you can write less code and still create high-quality, professional animations in less time. It helps developers control animations easily, such as timing, speed, direction, and effects.

What is Library

A library is a collection of pre-written code that helps developers perform common tasks without writing everything from scratch. Instead of building animations manually, we use a library like GSAP to save time, reduce errors, and improve performance.

Animation Libraries

There are different types of animation libraries in web development.
Some animation libraries are specially made for scrolling effects, some are used for transformations like moving, scaling, rotating elements, and some are used for advanced animations and interactions.

One of the most powerful and popular animation libraries is GSAP (GreenSock Animation Platform). It is widely used because it is fast, smooth, and easy to control.

In JS File

While using GSAP, we usually write all animation code inside a script.js or any JavaScript file. This file is linked to our HTML file, and GSAP animations are written there.

To start using GSAP, we use the gsap keyword. This keyword is the main object provided by the GSAP library, and all animations start from it.

The most commonly used method is gsap.to().
It is used to select an HTML element and animate it. The first parameter is the element selector (just like CSS), and the second parameter is written inside curly braces {}.

Inside the curly braces, we write property–value pairs, just like CSS.
For example: x: 100, opacity: 0.5, duration: 1
Each property and value is separated by a comma, exactly like objects in JavaScript.

GSAP mainly provides three basic methods:

  • gsap.to() 👉 Animates an element from its current state to a new state
  • gsap.from() 👉 Animates an element from a given state to its original state
  • gsap.fromTo() 👉 Animates an element from a specific starting state to a specific ending state

Using these methods, we can move, scale, rotate, fade, or transform elements smoothly from one state to another with high performance. 

gsap.to(".container",{
    key: value
})

GSAP Keys

It works very similar to the CSS animations you have already learned, but it is more powerful and flexible.

  • x is used to move an element on the X-axis, which means left or right (horizontal movement).
  • y is used to move an element on the Y-axis, which means up or down (vertical movement).
  • duration controls how long the animation will take to complete.
  • delay is used to wait before the animation starts playing.

You can apply transformations like translate, rotate, scale, etc., without writing the CSS transform property manually. The animation library handles it internally.

Important rule to remember:

  • Numeric values are written without quotes, for example: 1, 10, 360.
  • Values with units or text must be written inside single or double quotes, for example: "1rem", "100px", "red".

Animating multiple elements:

If you target multiple elements at the same time, there is a very useful property called stagger.

  • stagger: 1 means each element will animate one after another with a 1-second gap.
  • stagger: -1 means the animation will play in the reverse order.

Repeating animations:

  • repeat is used to repeat the animation.
  • repeat: 1 means the animation will repeat once.
  • repeat: -1 or repeat: "infinite" means the animation will loop forever.

Smooth back animation:

  • yoyo is a boolean property (it accepts true or false without quotes).
  • When yoyo: true is used, the animation comes back smoothly to its original position, just like a ping-pong effect.

GSAP Timeline

When we have multiple boxes and we want to animate them one by one, we usually give each box a different duration or delay.

For example:

  • First box animates
  • After it finishes, the second box animates
  • Then the third box animates

If we do this without a timeline, we have to manually calculate the duration and delay for every next box.
This becomes confusing and complex, especially when animations increase.

👉 This is where GSAP Timeline helps us.

Asynchronous vs Synchronous Animations

Before timeline, let’s understand two important concepts:

  • Asynchronous animation
    Elements animate independently.
    They start and end without waiting for each other.
  • Synchronous animation (Timeline)
    Elements animate in sequence.
    One animation waits for the previous one to finish.

👉 GSAP Timeline works synchronously by default.

Why Use GSAP Timeline?

Using timeline:

  • No need to calculate delays manually
  • Animations play step by step
  • Code becomes clean and readable
  • Perfect for complex animation sequences

Creating a Timeline

The first thing we need is a variable.

A variable is like a container used to store data.
You have already learned variables in CSS, and in JavaScript we create them using:

  • var
  • const
  • let

👉 If you want to skip deep JavaScript concepts, just use var.

Now create a timeline like this:

var ncs_time_line = gsap.timeline();

ncs_time_line.to("selector",{})
ncs_time_line.from("selector",{})
  • ncs_time_line is our variable name
  • gsap.timeline() creates a GSAP timeline
  • = assigns the timeline to the variable

Now our timeline is ready.

Using Timeline Instead of gsap

Once the timeline is created, we replace gsap with ncs_time_line.

In JS File
ncs_time_line.to(".box1", { x: 200 });
ncs_time_line.to(".box2", { x: 200 });
ncs_time_line.to(".box3", { x: 200 });

What happens here?

  • First .box1 animates
  • After it finishes, .box2 animates
  • Then .box3 animates

👉 All animations run automatically in sequence
👉 No delay calculation needed

var time_line = gsap.timeline();

time_line.fromTo(
  "div",

A Timeline in GSAP has built-in methods like .pause(), .play(), and .reverse(), which let you control the animation easily. You can use .pause() to stop the animation at any point, .play() to start or continue it, and .reverse() to play it backward. These functions make it easy to create interactive animations where you can start, stop, or reverse actions on demand.

What is ScrollTrigger in GSAP?

ScrollTrigger means controlling animations with scrolling. Normally, when we create simple animations, they play immediately as soon as the page loads. But with ScrollTrigger, the animation plays only when we scroll to a specific section or page.

For example, when you scroll down and reach the next section, the animation of that section will start at that moment. This makes animations more interactive and smooth, based on the user’s scroll.

To use ScrollTrigger, it is important to understand one thing: ScrollTrigger is a plugin. A plugin is an extra feature that adds specific functionality to a library or software. In this case, ScrollTrigger adds scroll-based animation control to GSAP.

By default, ScrollTrigger will not work unless we include its CDN file. That means we need two CDN files:

  1. One for GSAP core
  2. One for the ScrollTrigger plugin

You can find all GSAP and its plugin CDN links by visiting:
https://cdnjs.com/libraries/gsap

From there, copy the GSAP CDN and the ScrollTrigger plugin CDN, and link them in your HTML file. After that, ScrollTrigger will work properly.

Scroll Trigger in Action: 

gsap.from("firstScroll_selector", {});

gsap.from("secondScroll_selector", {
  scrollTrigger: "secondScroll_selector",
});

gsap.from("thirdScroll_selector", {
  scrollTrigger: "thirdScroll_selector",
});

Scroll Trigger Properties

We can give a separate scrollTrigger object in GSAP to have more control over scrolling animations. Inside this scrollTrigger object, there are several important properties:

  1. trigger – This is used to target the element (or CSS selector) that will trigger the animation when it comes into view.
  2. scroller – Use this if you want the scroll to be based on a specific scrollable element instead of the default window.
  3. start – Defines when the animation should start. You can use values like "top 80%" or "top center" to control the point at which the animation begins relative to the viewport.
  4. end – Defines when the animation should end. Like start, you can use percentages or positions like "bottom top" to control the ending point of the animation.
  5. markers – Set this to true if you want to see visual markers on the page showing exactly where the animation starts and ends.
  6. scrub – This allows the animation to be tied to the scrollbar.
    • Setting scrub: true makes the animation progress smoothly as you scroll.
    • You can also use a number like scrub: 2 to control the smoothness of the scrolling animation. Higher numbers make it smoother.
  7. pin – This pins an element in place while the animation runs. It keeps the element fixed until the scroll animation finishes.
gsap.from(".parent .child", {
  scale: 0,
  duration: 1,
  rotate: 360,
  opacity: 0,
  scrollTrigger: {
    trigger: ".parent .child",
    scroller: "body",
    markers: true,
    start: "top 70%",
    end: "top 50%",
    scrub: true
  },
});

Animation with Pin key: 

gsap.to("parent_element .text",{
    transform: "translateX(-210%)",
    scrollTrigger:{
        trigger: "parent_element",
        scroller: "body",
        markers: true,
        start: "top 0%",
        end: "top -150%",
        scrub:2,
        pin: true
    }
})

JavaScript Code Explanation

1. Pick things from the page:

let mouse_container = document.querySelector("#mouse_container");
let mouse = document.querySelector("#mouse");

Here, we are saying:

  • mouse_container is the big box where we want to watch the mouse move.
  • mouse is the small thing that will follow the mouse (like a dot or icon).

2. Watch for the mouse moving

mouse_container.addEventListener("mousemove", function(mouse_position){ ... })

This line says:

  • Hey! Whenever the mouse moves inside the big box, I want to do something.
  • mouse_position is just the current position of the mouse (where the mouse is on the screen).

3. Move the small thing to follow the mouse

gsap.to(mouse, {
    x: mouse_position.x,
    y: mouse_position.y,
    duration: 0.1,
    ease: "back.out(1.7)"
})

Here’s what happens:

  • gsap.to(mouse, {...}) 👉 We are telling the small thing to move.
  • x: mouse_position.x 👉 Move horizontally to where the mouse is.
  • y: mouse_position.y 👉 Move vertically to where the mouse is.
  • duration: 0.1 👉 Don’t jump instantly. Take 0.1 seconds to move.
  • ease: "back.out(1.7)" 👉 Make it smooth and bouncy, like it’s “following” the mouse instead of teleporting.
